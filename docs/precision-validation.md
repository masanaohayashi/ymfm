# 高精度演算層の検証結果

検証日: 2026-09-22。macOS / AppleClang 21.0.0 / C++14。
明示的なSIMD命令やfast-mathオプションは使用していない。

## 今回の完了範囲

- OPM / OPZの高精度演算層を追加し、既存整数コアを保持。
- float32 / float64を、パラメーター・波形テーブル・係数・音声演算・出力まで選択可能。
- 位相と位相増分は64 bit整数。
- 波形、EG、AM/PM、フィードバック、ノイズ振幅、ステレオ加算を浮動小数点化。
- SIMD化に備えたSoA配置とスカラー演算カーネル。
- 利用例、音色スナップショット変換、検証テストを追加。

## 数値誤差

振幅のフルスケールを1とした最大絶対誤差。
波形は8波形を計120万点の擬似ランダム位相と各境界点で検証。
アルゴリズムは8種類を、それぞれ3072サンプルの独立した解析式と比較。

| 検証 | float32 | float64 |
| --- | ---: | ---: |
| 波形テーブル＋補間 | 5.94993491143e-8 | 1.84566672951e-12 |
| 8アルゴリズムの音声出力 | 2.35659233930e-6 | 4.66730820659e-13 |

周波数→整数位相増分の除算をdoubleで行うことで、float32のアルゴリズム誤差は
変更前の2.11553340143e-4から上記の値に改善した。波形の高調波や強いFMに
対するアンチエイリアス処理の有無を示す数値ではない。

## 実行した検証

Release構成のCTestは3/3成功。

1. `original_all_cores`: 上流にある全コアの生成、保存復元、read/write、generate。
2. `precision`: 両精度の解析式比較、EG速度、44.1/48/96 kHz、位相境界、
   フィードバック、微小周波数差、OPZ機能、128ボイス、ブロック分割一致、
   C++動的メモリ確保ゼロ、入力検査、ノイズ多項式、音色インポート。
3. `original_regression`: OPM / OPZの8アルゴリズム、LFO、EG、レジスタ変更、
   key-offを含む出力ハッシュ、および保存状態からの257サンプルの再現。

`precision` はAddressSanitizer / UndefinedBehaviorSanitizer /
float-cast-overflow検査付きのDebug構成でも成功した。
旧コアのテストは通常のRelease構成で実施しており、このSanitizer結果は
新しい高精度経路の検証である。

公開ヘッダーを利用する例は、C++14の `-Wall -Wextra -Wpedantic -Wconversion
-Wshadow -Werror` で警告なし。

旧出力はコミット81aec25を別の一時ディレクトリに抽出し、独立ビルドした結果と比較。
OPMは `9652c829404dbc75`、OPZは `8e86f0e4e6264d91` で一致。
元から追跡されている `src/` ファイルには変更を加えていない。

## 初期版（00e09ac）のスカラー処理時間

Releaseの `ymfm_precision_example` を実行。
128ボイス、48 kHz、48128フレーム（約1.003秒）、4オペレーター、OPZ波形、
2系統LFO、フィードバックを使用。

| 演算型 | 実測wall time | 出力二乗和のchecksum |
| --- | ---: | ---: |
| float32 | 0.3774秒 | 19.591017 |
| float64 | 0.4367秒 | 19.591471 |

単回のローカル測定であり、音声コールバックの締切保証や他機種での性能保証ではない。
テーブル初期化と音色設定は計測区間外。測定例はリポジトリ内で再実行できる。

## CPU負荷修正（2026-09-23）

無音時も全ボイスのLFO・ミックスを毎サンプル処理していた問題を修正。
EGが全て終了した時点でボイスを除外し、全ボイス無音ならバッファのゼロ埋めのみ行う。
ノイズ設定の有無には依存しない。発音中のexp2・ldexp・fmod呼び出し、除算も除去した。
指数変換はRealのテーブルと局所多項式を使用し、ピッチ倍率は4オペレーターで共有する。

同じベンチマークを初期版00e09acと修正版でそれぞれReleaseビルドした比較。
128スロット、16384サンプル、3回の中央値。セットアップは計測外。
releasedは128ボイスを発音後、Key Offして全EGが終了した状態（ノイズ設定あり）。

| 条件 | float32 初期→修正（秒） | float64 初期→修正（秒） |
| --- | ---: | ---: |
| 未発音 | 0.023832 → 0.000019 | 0.020638 → 0.000026 |
| 全EG終了 | 0.018857 → 0.000020 | 0.020533 → 0.000020 |
| 1ボイス発音 | 0.019907 → 0.001071 | 0.022545 → 0.001223 |
| 128ボイス、LFOなし | 0.092149 → 0.044541 | 0.098720 → 0.046037 |
| 128ボイス、LFOあり | 0.130761 → 0.058080 | 0.150059 → 0.060658 |

ホスト全体のCPUメーターではなく、演算層単体のローカル測定。
利用例の48128フレームは修正後float32で0.1899秒、float64で0.1783秒。
実行条件により変動するため、性能比較は通常のCTestとは分離している。

```sh
python3 scripts/check-precision-performance.py
python3 scripts/check-render-kernel.py
```

指数近似の最大相対誤差はfloat32で1.62433937412e-7、float64で2.44249065418e-15。
上記の波形・アルゴリズム最大誤差は変わらない。
ReleaseのCTestは4/4成功。追加のrender_kernel_auditは両精度のrenderを
機械語へコンパイルし、外部関数呼び出しと除算命令を検査する。
この環境での外部シンボルはゼロ埋め用のbzeroだけだった。
休止・再発音、LFOの経過時間反映、乱数のジャンプ、ブロック途中のEG終了、
ノイズ設定のある休止状態を回帰テストへ追加した。

修正後もAddressSanitizer / UndefinedBehaviorSanitizer / float-cast-overflow付きの
precisionテストは失敗ゼロ。公開ヘッダー利用例の厳格警告検査も成功した。

## 1ボイス時のループ除去（2026-09-23）

Apple M2 Max / AppleClang 21 / C++14 / -O3。d0a1403の生成アセンブリでは、
1ボイスでも各オペレーターで走査ループの準備と終端判定が残っていた。
アクティブ数が1の場合をテンプレートで特殊化してループを除去した。
EGの終了によりブロック途中で発音数が変わるため、分岐はサンプル単位で行う。

同一ベンチマークを前後のヘッダーでビルドし、5回の中央値を取得。
実行順を交互にした3組の中央値で比較した結果:

| 条件 | d0a1403（秒） | 修正後（秒） | 処理時間の減少 |
| --- | ---: | ---: | ---: |
| 1ボイス float32 | 0.001087917 | 0.000898708 | 17.4% |
| 1ボイス float64 | 0.001243750 | 0.000980542 | 21.2% |
| 128ボイス＋LFO float32 | 0.057664625 | 0.057470583 | 0.3% |
| 128ボイス＋LFO float64 | 0.059938750 | 0.059666208 | 0.5% |

ベンチマークを8・32ボイス、定常発音、16・1024サンプルのブロックにも拡張した。
複数ボイスの差はほぼ測定のばらつき内であり、多ボイスの高速化を示す結果ではない。
1ボイスの回帰条件は次で再実行できる:

```sh
python3 scripts/check-precision-performance.py d0a1403 --repeats 5 --case f32_one --case f64_one --min-speedup 1.1
```

全8アルゴリズム・両精度で、1ボイスの経路と無音の追加ボイスがある通常経路を比較。
ブロック途中の追加ボイス終了と再発音を含め、出力・位相・EGは完全一致した。
Release CTest 4/4、Sanitizer検査、厳格警告検査が成功。

検討したボイス単位へのループ統合、全スロット発音用の直接インデックス化、
振幅キャッシュ、指数テーブル縮小は、安定した速度改善を示さず採用していない。
明示的SIMDはまだ未実装。多ボイス発音中の負荷削減は引き続き必要。

## 定常サステインのEG更新省略（2026-09-23）

サステイン増分と補償加算の残差がともにゼロになったオペレーターを
sustain_hold状態へ移し、EGの加減算・状態書き戻しを省略する。
音声・位相・変調は通常通り計算する。set_voiceで非ゼロのサステインレートを
設定した場合は通常の更新へ戻り、Key Offと再発音も従来通り遷移する。
非ゼロの補償残差を切り捨てて停止することはない。

Apple M2 Max / AppleClang 21 / C++14 / -O3、7回の中央値。
比較対象は直前の3435b2e、128ボイス、16384サンプル。

| 条件 | 3435b2e（秒） | 修正後（秒） | 処理時間の減少 |
| --- | ---: | ---: | ---: |
| 定常・LFOなし float32 | 0.041011 | 0.037471 | 8.6% |
| 定常・LFOなし float64 | 0.042778 | 0.039646 | 7.3% |
| 定常・LFOあり float32 | 0.054166 | 0.051486 | 4.9% |
| 定常・LFOあり float64 | 0.056590 | 0.053717 | 5.1% |

```sh
python3 scripts/check-precision-performance.py 3435b2e --repeats 7 --case f32_steady_dry --case f64_steady_dry --case f32_steady_lfo --case f64_steady_lfo --min-speedup 1.04
```

OPM/OPZ・両精度で、停止後のレート変更、TL・AM・OPZ shift編集、Key Off、
再発音を検査。Release CTest 4/4、Sanitizer、厳格警告検査に成功した。
振幅の追加キャッシュはLFO使用時に不利だったため採用していない。
この改善は定常サステインが対象であり、変化中のEGを間引くものではない。

## 定常波形の専用カーネル（2026-09-23）

連続したボイススロットで、対象オペレーターのEGが全て定常サステイン、LFOなしの
場合をブロック先頭で判定する。振幅変換をブロックに1回だけ計算し、位相・FM・波形評価を
専用カーネルで処理する。ノイズ使用中の第4オペレーターは通常経路を使う。
通常経路と高速経路の選択をブロック外側で特殊化し、適用外の演算へ毎サンプルの判定を追加しない。
ボイス終了時は適用フラグを解除し、音色・LFO等の編集後は次のrenderで再判定する。

AArch64/Clangではfloat32を4レーン、float64を2レーンで評価する。
各区間の係数を128 bitロードして転置し、同じ順序のHorner式をFMAで計算する。
機械語監査でfmla.4sとfmla.2dの存在を確認する。位相精度、波形テーブル精度、
EGの時間刻みは変更していない。その他の環境とYMFM_PRECISION_DISABLE_SIMD指定時は
スカラー評価を使用する。

Apple M2 Max / AppleClang 21 / C++14 / -O3、7回の中央値。
比較対象は直前の1d823eb、128ボイス、16384サンプル。

| 条件 | 1d823eb（秒） | 修正後（秒） | 速度比 |
| --- | ---: | ---: | ---: |
| 定常・LFOなし float32 | 0.038013 | 0.016475 | 2.31倍 |
| 定常・LFOなし float64 | 0.039985 | 0.015461 | 2.59倍 |

この速度比は定常計算の省略と専用カーネルを合わせた結果であり、SIMD単独の速度比ではない。
同じ専用カーネルで波形だけスカラー評価に戻した比較では、float32はほぼ同等、float64は数%差だった。
EG変化中・LFO使用中・非連続スロットは今回の高速化対象外。

```sh
python3 scripts/check-precision-performance.py 1d823eb --repeats 7 --case f32_steady_dry --case f64_steady_dry --min-speedup 1.8
```

3/4/5/8/17/123ボイス、開始スロット5、混在アルゴリズム・波形、非ゼロの定常減衰量で
通常カーネルと出力・位相・EGが完全一致した。途中のノイズ/LFO/TL変更、Key Off、
ボイス終了と再発音も確認した。波形パケット単体も10万組のランダム位相でスカラーと完全一致。
両経路のrender時動的メモリ確保はゼロ。
Release CTestはスカラー専用ビルドも加えて5/5成功。
Sanitizer、厳格警告、両経路の禁止関数・除算命令監査にも成功した。

## 定常サステイン＋LFOへの適用拡大（2026-09-23）

高速経路でもピッチ増分を毎サンプル更新するようにし、ピッチLFOがあるオペレーターへ
適用を拡大した。AMがある場合はEG側の一定減衰量だけをブロック先頭で計算し、
AMの加算と指数変換を毎サンプルのSIMDパケットで行う。
ピッチ／AMの有無はオペレーターごとに判定し、固定周波数のピッチ変調指定も保持する。
LFOの更新頻度・式、指数近似の係数・次数は変えていない。

Apple M2 Max / AppleClang 21 / C++14 / -O3、7回の中央値。
比較対象は直前の1313504、128ボイス、16384サンプル。

| 条件 | 1313504（秒） | 修正後（秒） | 速度比 |
| --- | ---: | ---: | ---: |
| 定常・ピッチLFO float32 | 0.068160 | 0.041659 | 1.64倍 |
| 定常・ピッチLFO float64 | 0.070851 | 0.043098 | 1.64倍 |
| 定常・ピッチ＋AM float32 | 0.072960 | 0.054093 | 1.35倍 |
| 定常・ピッチ＋AM float64 | 0.075218 | 0.058572 | 1.28倍 |

各行は同一ベンチマーク・同一測定回での比較。以前の測定回と絶対時間を直接比較しない。
定常・LFOなし、EG変化中、1ボイスの比較も行い、5%の回帰判定を通過した。

```sh
python3 scripts/check-precision-performance.py 1313504 --repeats 7 --case f32_steady_pitch --case f64_steady_pitch --case f32_steady_lfo --case f64_steady_lfo --min-speedup 1.15
```

指数パケットは範囲端点と10万組のランダム入力でスカラー評価と完全一致。
音声経路は5種類のLFO、固定周波数とピッチ変調指定の混在、AM有効／無効の混在で
通常カーネルとの出力・位相・EGの完全一致を確認した。
比較対象は無音の追加スロットで高速経路を使えなくし、確実に通常カーネルを通す。
Release CTest 5/5、Sanitizer、厳格警告、両経路の禁止命令監査が成功。
EG変化中や非連続スロットでの多ボイス演算はまだ通常経路であり、追加最適化の対象。
